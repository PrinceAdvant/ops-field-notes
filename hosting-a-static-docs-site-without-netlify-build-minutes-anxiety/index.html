Hosting a static docs site without Netlify build minutes anxiety

Static site hosts compete on build minutes, bandwidth and form/feature addons. If your docs site is a Hugo or VitePress build that changes a few times a week, you can often leave Netlify without losing quality.

Cheap reliable patterns

  • GitHub Pages or GitLab Pages for public docs with Actions/CI doing the build.
  • Object storage (S3, R2, B2) plus a CDN for high bandwidth and custom domains.
  • A 1 GB VPS with Caddy serving ./public if you already operate servers and want one place for TLS.

What you give up

Netlify identity, split testing and some form handling go away unless you replace them. For docs, that is usually fine. For marketing landing pages with A/B tests, budget replacements before cutting over.

Cutover checklist

Build in CI, upload artifacts, enable HTTPS, set redirects for old paths, then flip DNS. Keep the Netlify site read-only for a week in case you missed a redirect.

Watch cache headers after the move; a missing Cache-Control on hashed assets shows up as bandwidth bills, not as a broken page.
