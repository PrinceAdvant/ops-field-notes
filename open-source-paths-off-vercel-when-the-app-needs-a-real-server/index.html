Open-source paths off Vercel when the app needs a real server

Vercel is excellent for frontends and lightweight serverless functions. Friction appears when you need a persistent WebSocket server, a Python worker, a native module that fails in the function runtime, or a predictable monthly bill for always-on backends.

What open-source alternatives try to replace

Self-hosted platforms give you git-based deploys, HTTPS, env management and often preview environments on hardware you control. You trade away global edge PoPs and zero-ops functions for SSH access and Docker semantics you can debug locally.

Choosing among them

Look at language support (Dockerfile vs buildpacks), how databases are provisioned, whether background workers are first-class, and how painful upgrades are. Coolify, Dokploy, CapRover, Dokku and Peon all sit in this space with different UX bets. For static-only sites, a plain nginx container may be enough and a full PaaS is overkill.

Migration notes

Move environment variables first, then the primary domain with a low TTL, then background jobs. Keep Vercel as a temporary frontend origin until the new host's TLS and caching behave.

Measure TTFB and error rates for a day on the new host before deleting the old project.
