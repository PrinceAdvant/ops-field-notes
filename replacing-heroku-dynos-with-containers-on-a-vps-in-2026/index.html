Replacing Heroku dynos with containers on a VPS in 2026

Heroku still works, but dyno pricing and addon bills push many teams to own the runtime. The hard part is not Docker itself; it is recreating the conveniences you stopped noticing.

Buildpacks become Dockerfiles

Start from the same stack your buildpack used (official language images). Copy Procfile process types into Compose services with explicit commands. Run the release phase (migrations) as a one-off before traffic switches.

Addons become services you operate

Postgres, Redis and S3-compatible storage move to managed cloud DBs or containers you back up yourself. Prefer a managed database if you do not want WAL babysitting; keep Redis small and disposable if it is only a cache.

Pipelines become environments

Review apps become either ephemeral Compose projects on a shared staging VPS or separate preview hosts. You will miss one-click PR apps until you automate DNS and TLS; budget a day to script that if previews matter.

Ops you inherit

Log drains become journald or a small Loki/Vector stack. Scheduler becomes cron or a worker service. Autoscaling becomes either vertical resize or a second node later.
